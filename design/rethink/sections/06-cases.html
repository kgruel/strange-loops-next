Three cases

The layer 1 model tested against three real stores: a novel, task orchestration, and the team's shared platform knowledge. Each one surfaced exactly one new idea, and none needed new machinery.

CaseWhat it surfaced
NovelThe time axis can be a declared field (chapter, story time), not only occurred or emitted.
OrchestrationSpecs are templates; vertices are instances created at run time, each with its own anchor.
Team storeWeights are records about observers, applied by a vertex at read time. Promotion is a stance.

The novel

A hand-built store with one steward, made strict early because its shape is designed on purpose. Two vertices ask two questions of the same records: what's the manuscript? and is the timeline consistent? The JS front end is a lens; edits made in it are new records.

Weighting by observer
loops emit tenure years:=20 domain=platform --about sl:director    # by sl:team-root
loops emit tenure years:=14 domain=platform --about sl:a1          # by sl:team-root

{ "vertex": "platform-knowledge",
  "note": "Ranked by tenure, each with its time.",
  "from": [{ "store": "team", "kind": ["decision", "process", "history"] }],
  "fold": { "by-thing": { "collect": true, "by": "about", "weight-by": "tenure" } } }
  • Weights are records: statements about observers, made by someone, so relative to whoever makes them.
  • Weighting lives in a vertex, so a new developer, an auditor and the director can each weight the same store differently.
  • Tenure varies by domain. Weight by tenure and evidence: who touched the code a record is about, and whose earlier claims were later affirmed. Both are already records.
  • Weighting ranks, never hides. In a 20-year codebase, the junior developer's recent observation is often the one that catches the outdated assumption.
  • Weight ranks a collection, never Latest. Corrected in version 12: this snippet used to read "latest" weight-by, which either buries this morning's observation under 2019 seniority or does nothing. "Director says X · two devs observed Y since" is a Collect ordered by weight that shows each record's time.
Promotion: what travels depends on the act

A record copied verbatim isn't a new record. With content addressing, it's the same record, with the same hash, held in two stores, with its original observer, signature and emitted intact.

ModeLands in the team storeProvenance
Verbatimthe original record + a promote stancecomplete: it is the original
Restateda new record with derived-from: <hash>a pointer: an original exists, unreadable to the team
Summarizeda tick from a personal vertex, covering by hashpointers, with an optional bundle
Agent-proposedWren drafts any of the above; your stance makes it countas the chosen mode, plus Wren's grant

In every mode the promote stance is what the team store's policy checks. Which mode will dominate is a usage question that can't be answered yet; the design supports all of them equally.
