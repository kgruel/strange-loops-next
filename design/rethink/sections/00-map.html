Where we are

Arrival tried to make a single-writer custody log carry every kind of sharing. Going back to the roots: records form an observed set, meaning binds at read, the observer is first-class, and stores avoid coordination by being immutable, so they never need an authority. For the whole picture built up one step at a time, start with Scenarios; for everything at once, see the worked example.

Decision ledger

Each decision is written as a record, the way the system would hold it. Folded in version 31: 92 entries became 33, grouped by layer. Version 32 settled three model questions raised by two outside reviews. The conversation turns in Sources keep how each was reached.

How the conversation moved
  1. Started as a language question: rewrite in something faster and easier to install.
  2. Narrowed to the real pain: Arrival grew out of hand while trying to make stores shareable and mergeable by default.
  3. Widened again to the full topology: personal stores, ingestion, composition, ticks in agent orchestration. Git is one place a store can live, not the only one.
  4. Then went back to first principles, layer by layer. Layer 0 (the record) and the observer took most of the time, which is right, since everything else is built on them.
  5. Layer 1 closed against three real cases. Composition opened by asking what a thing is, and moved identity from the fold into the record.
  6. Resolution split ticks into content and witness, and found that most "late ticks" are really revisits.
  7. Places kept erasure small, split the old vertex file four ways, and a worked example tested everything together.
  8. Sharing needed nothing new: union, admission, witness-style cuts and key bindings. The work went into keys, presence and agents.
  9. Build chose Go once bindings dropped out, then Rust in version 31, once phones and extensions needed the core itself. Horizons collected what the design makes cheap: editable lenses, selective disclosure, knowledge as a build.
  10. Versions 26 to 31 walked the local API, MCP and the CLI, ran a vocabulary pass (seal retired, vertex kept), made specs JSON, and moved the build to Rust, with the page folded into a build brief.
  11. Version 32 took two outside reviews and settled three things in the model: folds come in two families, both proved to depend only on the set; a payload is here, withheld or erased, and supersession never reads it; a tick is a value, stored only as a signed record. A vertex became the hash of its spec, which removed vertex anchors and vertex standing.
  12. Version 34 asked what the model actually proves. Four holes, each reproduced against it: selection ran before supersession, two places' forms of one record broke "the set decides", prev was global, and about was one key. Now prev is succession within a thing, supersession runs over everything held, erasure is a record, and about is a set.
  13. Version 33 caught the repo up: the model took the vocabulary (protocol/, LatestBy, Stored), PRs 1 and 2 merged, and step 2's model went up as PR 4. Modelling the spec found that payload tests must apply after supersession, or a filter brings back what was replaced.
  14. A second opinion from Gemini found seams the page had papered over: a weighted Latest, prev as one pointer, SKOS left in the example. Each closed with parts already in the model.
  15. Walking the LSP end to end replaced "paths as dated names" with birth keys read along each branch's history, and made git segment files close on commit. Nothing entered the core.
  16. Walking web annotation found federation already there: each person's own store, composed. Publishing became a declaration on the store, and admission became the spam filter.
  17. Walking context by tick id turned into a walk about references a reader can't fully see: five states, shown honestly, with provenance carried into an agent's context.
  18. Extending it to the whole pipeline, from a design thread to a cloud run and back, separated what a place holds from what an agent sees, and made the trip up a disclosure and the trip home a plain sync.
  19. Unpacking knowledge as a build gave every result two names, so work stops where results stop changing, and stated plainly what privacy here is: withholding, not hiding.
  20. Breaking the editable lens on purpose changed its contract, not the record: a base names its lens and audience, a committed render is a promotion, and absence is never an edit.
  21. Drawing the limits found the spec's predicates drifting toward a language. They closed to a typed set, parse pipelines left for collectors, and anything more gets recorded by an observer.
  22. Asking what a size budget is for turned one line count into four budgets, and a proof language found a role outside the build: proving the fold laws and writing the vectors the core must pass.
  23. Choosing Lean 4 over Bend 2 brought the lens laws into reach for the syntax we own, and replaced unit tests with four checks that never take their answer from the code they check.
  24. Laying out the repo turned the budgets into structure: a core module with nothing to require, one public package, and a store of its own decisions.
  25. Step 0 proved the first laws in a day and found that the law worth proving was not "incremental = batch" but "the set decides".
  26. Step 1, built overnight, found two things a design walk wouldn't: an off-by-one in number formatting that the standard's own data caught, and that a sum over floats can't satisfy "the set decides".
