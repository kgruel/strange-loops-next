Where we are

  • Steps 0, 1 and 2 are done. Kyle closed step 2 on 2026-11-20: loops emits, reads and folds for one person, signed, over .loops/.

  • Step 4 (ticks) is done. Kyle closed it on 2026-11-22: loops tick <spec> writes a tick, loops tick --check <id> checks one, and a tick written on one machine checks same on a second. A tick can cover a cut, by time or by ids, and a write can state a tick as its base. Boundaries, markers and the runner were never part of the step and are not built.

  • Lean (the model) and Rust agree on every vector; the JavaScript on every vector from before ticks (649 files). From ticks on, a piece is built in Lean and Rust; the JavaScript is frozen at what it has, as a trial for step 4 (ruled 2026-11-21). Kyle ruled on 2026-11-23 that it stays frozen, as the rule (W3b).

  • One outside user: rex-tools, a chat room over the loops CLI. It found a slow read path (fixed 2026-11-21) and a gap in --values (fixed the same day).

  • The old Python loops is still first on PATH on Kyle's machine, and his day-to-day stores are still the old ones.

The evidence and its counts are kept where they are made: the law index, vectors, the fuzz report, the mutation report and Rust boundaries. The changelog entry of 2026-11-21 has them as they stood on that day.

Reference

Why Rust. Small writers can use JSON in any language. Phones and browser extensions need embedded readers, and Rust runs there without a server. Exhaustive enums expose missing cases, and Lean's closed types map directly to enums. This is design rationale; no bindings exist.

A reader reaches the core in three proposed ways. All three speak the same JSON shapes.

  • Local server: a browser, LSP or MCP client speaks JSON-RPC to loops serve, which reads .loops/ on disk. This suits a laptop and keeps keys out of the browser.

  • WebAssembly: loops-wasm runs inside the page or extension, over browser storage or files the reader picks. This suits an annotation extension, static hosting and an offline web app.

  • Native bindings: loops-ffi, through UniFFI, runs inside a Swift or Kotlin app, over the app's own storage. This suits a phone.
