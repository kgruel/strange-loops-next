What rests on what

A line from one law down to another says a proof of the first uses a theorem of the second, directly or through lemmas no law names. Lean recorded every one of them; lake exe proofs reads them out of the checked proofs.

The stack only rests downward: the build fails if a proof ever leans on a layer above its own. A law's layer is declared, not derived; that check is all the proofs say about it.

A proof by computation (decide) evaluates definitions and uses no theorem, so it draws no line.

Point at or tap a law to follow it, or a line to see the theorems that make it. Enter, or a second tap, opens the law's card.

The map is laid out when the page is built: the same laws and proofs always draw the same map.

id.digest

Round trip

An id's digest has exactly 32 bytes. Reading these bytes gives the same id. Two ids have the same text only when they are equal.

The model keeps every record id and reference below 2256. Reading any 32 bytes gives an id below 2256. Writing that id back gives the same 32 bytes. The model's SHA-256 returns 32 bytes. With the model's SHA-256, an id written from bytes equals the id written from the number. The model does not derive fold records from these hashes.

laws.md An id's digest has exactly 32 bytes. Reading these bytes gives the same id. Two ids have the same text only when they are equal. Reading any 32 bytes gives an id below 2^256. Writing that id back gives the same 32 bytes.
